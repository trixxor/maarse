Features · Explanation

Public alerts

Signed warnings that can be trusted without a server.

TL;DR

What: A public alert is a warning signed by a trusted issuer, like a cell-broadcast alert but over the mesh. Anyone can check it offline. It appears as a banner that no chat message can imitate.

Why: In a crisis the mobile network may be down, and a warning is only useful if people can trust it. A signed alert can be checked without any server, and cannot be faked by someone typing in a chat.

Strengths

  • Unforgeable: signed with an issuer key that is separate from any node identity
  • Cannot be replayed: serial number, issue time and expiry
  • Cannot be faked as text: shown as a separate banner, and typing on the alert channel is refused
  • A certificate from a root key limits what an issuer may send
  • Exercise and test alerts are clearly marked and quiet

Good to know

  • Trust is whoever holds the root key: protect it and keep it offline
  • Repeaters cannot yet verify alerts, so they do not boost them
  • Checking in the firmware and the Android app without a host is not built
  • Revocation lists and cryptographic two-person signatures are not built

Actual, exercise and test

Only an actual alert that is severe or extreme and still valid becomes a banner. Exercises and tests are striped and quiet. An update or a cancel refers to the alert's number and can only come from the same issuer. Issuing an actual alert needs a tick that a second person has checked it (the lesson from the false missile alert in Hawaii).

Who can issue one

A receiving host shows an alert only if the issuer key is trusted directly, or has a certificate signed by a trusted root key. A certificate names the issuer (for example "Beredskab Nord") and limits which events it may send, its highest severity and how long it is valid. The certificate is sent before the first alert and at most hourly after that, and receivers cache it. Issuing is done in the dashboard form under Network → Alerts on a host that has an issuer key.

Format and flood control

  • An alert is a channel message on the hashtag channel #bulletin, signed with an Ed25519 issuer key. The old v1 bulletin (0xB1, 69 bytes of overhead) is still accepted from trusted senders, valid for 24 hours and shown once.
  • Alert packets go before other channel traffic, but at most 8 per minute per node, because the channel key is public and junk must not crowd out other traffic.
  • A node without a clock uses the newest verified alert's time as a lower bound. An alert issued far in the future is dropped.
  • Each alert is shown once. An old alert sent again after its expiry is dropped.
