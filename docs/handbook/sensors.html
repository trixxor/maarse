Sensor nodes

A board that watches something and tells you when it matters.

TL;DR

What: A sensor node is a Må:rse board that reads things (temperature, a door, a soil probe), sends readings and alarms to its owners, and sleeps in between. You set it up in a designer, in sentences like "when Temperature is below 10 °C for 2 readings, send an alarm". The designer turns that into a small recipe that the node runs by itself.

Why: A cabin, a greenhouse or a mailbox far from Wi-Fi can send an alarm over the mesh and run for a long time on a battery. The alarm works even when your phone or PC is off, because the recipe lives on the node.

Strengths

  • Plain-language designer in the web client and the Android app
  • Starting points: frost alarm, room climate, air quality, motion alarm, mailbox
  • Owners are people, up to four, each with the readings they choose
  • About 55 seconds of radio time a day, 0.06 %
  • A recipe cannot hang or damage the node: no loops, no free-form code

Good to know

  • The firmware compiles for XIAO nRF52840 and Heltec V4, but sleep current, the BME280 on a real board and ESP32 deep-sleep wake have not been measured or run
  • First setup is over USB from a computer; later changes go over the radio
  • Not supported yet: DHT11/22, ultrasonic, 1-Wire, serial sensors (GPS), 5 V modules

released Core, host and both user interfaces are built and tested with unit tests and screenshots. Not verified on hardware.

The designer

In Nodes → Sensors you see your sensors with their last values, alarms in red, quiet sensors in amber, favourites first. To set one up, choose a starting point, adjust the sentences, watch a simulated day, and send it to the node. The designer shows how much of the 256-byte recipe is used and how much radio time a day it costs.

Limits8 inputs and outputs, 8 rules, 3 steps per rule, 64 bytes of alarm text, 256 bytes in all, at least 30 s between cycles

What you can connect

  • I2C chips: BME280/BMP280, SHT30/31/35, SHT40/41/45, AHT20/21/DHT20, BH1750 (light), MCP9808, TMP117, MCP9600 (thermocouple), SCD41 (CO2), ADS1115 (four analogue inputs), ADXL345 (motion), MLX90614 (infrared thermometer).
  • Grove modules on one pin: PIR, button, touch, reed switch, tilt, vibration, flame, Hall, infrared obstacle, relay, LED, buzzer, and analogue ones that work at 3.3 V: soil moisture, water, light, sound, rotary knob, UV.
  • Your own I2C sensor by describing its address, set-up bytes and how to read the number. The designer cannot try the chip, so check the numbers against the data sheet.

The catalogue is data, not code. It is a set of files in the repository, signed with the release key and published on GitHub, and a host checks for updates about once a day. A node needs no update for a new I2C chip, because the recipe carries the description of how to read it.

Mailbox and wake-by-pin

A pin is normally read once per cycle, so an opening shorter than the cycle is missed. For doors, buttons and mailboxes, turn on Wake the sensor when this pin changes: the pin wakes the node from sleep the moment it changes, and an edge rule then fires at once.

  • Wiring: a normally open reed switch that closes when the flap opens, between the pin and GND, with a pull-up. A switch that is closed while nothing happens would lose about 70 µA.
  • nRF52840: any free pin (D0, D6, D7), woken by the pin's PORT event.
  • ESP32-S3 (Heltec V4): only the RTC pins GPIO 3, 4 and 6; the pin is armed before deep sleep.
  • A pin still at its wake level when the node goes to sleep is not armed, because it would wake the node at once.

The sensor catalogue entry for a sensor needing a firmware driver (today only the BME280) works only when the firmware has it. Any entry must carry tests with numbers from the data sheet, and CI refuses an entry whose test fails.
