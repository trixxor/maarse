Roles · Explanation

Host

The program that joins your radio to the rest of the network.

TL;DR

What: A host is the Må:rse program that runs on a PC, a server or inside the phone app. It is a node itself, and it is also a gateway: it attaches radios, joins the internet backbone, keeps your history and a post office, and serves the web client in your browser.

Why: A radio alone has little memory and a small display. A host adds storage, a screen and the internet, and joins radio areas into one network.

Strengths

  • The web client, the Android app and the Windows tray all talk to a host
  • Keeps your messages, files and mail for days, even when your phone is off
  • Joins LoRa, Wi-Fi radios, serial modems, KISS and the TCP/UDP backbone
  • Acts as a post office with three copies across the backbone
  • Runs as a Windows service or a Linux systemd service, with signed updates on Windows

Good to know

  • It needs a computer or a phone that stays on to be useful as a gateway
  • History is stored unencrypted on disk by default (kept 90 days); turn it off if that matters
  • A host that is reachable from the internet should require an access key

tested end-to-end on a PC. bench-tested with Heltec V4 and XIAO nRF52840 as modems.

What a host does

What a host does

  • Be a node with its own identity and address
  • Serve the web client and a WebSocket for the app
  • Attach LoRa radios over USB serial, a Wi-Fi modem, KISS (for example Direwolf) or a directional trunk
  • Join the TCP and UDP backbone, run a DHT and find other hosts
  • Keep history, a post office and a file mailbox
  • Serve maarse:// pages and run an MQTT bridge to Home Assistant
  • Update the firmware of the radios attached to it, signed
  • Run as a service with a live log page

What a host is not

  • Replace a repeater on a hilltop: the radio on it is the repeater
  • Reach people by radio on its own: its radio range is whatever the attached radio gives
  • Be reached by phones on mobile networks directly: mobile networks use CGNAT, so a host needs a public address, a forwarded port or a VPN

The post office in a host

When a recipient is offline, your host keeps the message and sends copies to three other hosts over the backbone. See mailboxes and carry for how it works end to end. Measured in the simulator, a traveller who was offline from Aalborg to Rønne received 76 % of the mail written while away with post offices, against 4 % with no mail design, and 36 % with the older single home-host design, at about 2.5 times the airtime in that run. See simulation results.

Wi-Fi: a board as the host's antenna

A Heltec V4 or XIAO ESP32-S3 can join Wi-Fi (a phone hotspot on a hilltop is enough) and keep a TCP link to a host. It has two modes.

ModeWhat it doesWhen the link is lost
Mesh node (default)A node of its own that peers with the host over the backbone and keeps working if the host goes away.Keeps routing as a node
LoRa modem for the hostThe host's antenna over Wi-Fi: forwards raw LoRa packets with their signal quality to the host and sends what the host asks for. It does not route or announce.After 60 s it works as an ordinary node with its own identity, so the LoRa group around it keeps working

The firmware contains both Bluetooth and Wi-Fi but runs one at a time. Hold the PRG button for 3 seconds to switch. A modem key makes the host check that the radio is really yours. bench-tested joining a WPA2 network, DHCP, ping, linking to a host, and switching between Bluetooth and Wi-Fi on a Heltec V4.3. Not tested: messages from LoRa through the Wi-Fi link, and the XIAO ESP32-S3.

Settings, not flags

Everything is set in the web client under Settings and is stored in settings.txt in the host's data folder. A host that is a service restarts itself when you save. By default every client joins the open backbone; take it out under Settings to stay off it.
