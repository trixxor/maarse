# Languages (i18n)

Everything a person reads in Må:rse can be shown in the person's language:
the Android app, the PC web client, the server pages (login and dashboard),
the web flasher, the Windows tray app and the Windows installer.

Languages built in today: **English** (the texts in the code) and **Dansk**.

## Choosing the language

* **Automatic** is the default. The app follows the device: the language of
  Android, the language of the browser, the Windows display language.
  If the device language has no language file, English is used.
* **Settings** lets you choose by hand, and it wins over the device:
  * Android app: **Settings > App > Language** (Automatic, English, Dansk).
  * PC web client: **Settings > Language** (it cycles Automatic, English,
    Dansk, ...). The choice is kept in the browser. The server pages
    (login, dashboard) and the flasher follow the browser language the
    same way.
* The Windows tray app and installer follow the Windows display language
  (the installer asks only when Windows uses a language it does not have).

A text that is missing in a language is shown in English. There is never a
raw key on the screen.

## What is not translated

* Host logs, command-line help and flags, `settings.txt` option names.
* The Heltec display (stays English).
* Protocol names and identifiers, file names, keys.
* Text that people write: messages, names, channel names, page content.
  (Android `RawText`, web `translate="no"`.)
* The legacy `maarse-tray` Scheduled-Task tray (the Windows installer uses
  `maarse.exe`, which is translated).

Messages the system creates itself (alerts, delivery receipts, statuses) are
translated where they are shown. The wire format does not change.

## How it works

The English text in the code is the key. No text is renamed to be
translated. A language file maps English text to the translation:

```json
{
  "meta": { "code": "da", "name": "Dansk" },
  "texts": {
    "Settings": "Indstillinger",
    "Sent {0} messages": "Sendte {0} beskeder",
    "%d KB": "%d KB"
  }
}
```

* `{0}`, `{1}` ... (and in the Android app also `%d`, `%.1f`, `%s`) stand for
  the variable parts of a text. The variable parts are translated too, so
  `"Status: {0}"` works with a translated state. A translation may leave a
  part out (for example a plural ending).
* White space in a key counts as one space.
* A missing or empty translation stays English.
* A paragraph that is made of several known sentences is translated sentence
  by sentence.

Where the file is used:

| Place | How |
|---|---|
| `i18n/<code>.json` | The one source, shared by everything below. |
| Web pages | `maarse-client/i18n.js` translates text, `title`, `placeholder`, `aria-label` and `alt`, also for what the page builds later. `alert`, `confirm` and `prompt` are translated too. The host serves `/i18n.js`, `/i18n/index.json` and `/i18n/<code>.json`. |
| Android app | `I18n.kt` and `Translator.kt`. The screens' `Text` goes through `ui/I18nText.kt`, which translates first. The files are copied into the app (assets) when it is built. |
| Windows tray app | `maarse-desktop/src/i18n.rs`, built in. |
| Windows installer | `[Languages]` and `[CustomMessages]` in `packaging/windows/maarse.iss`. |

## Adding a language

1. `python tools/i18n_check.py --new de` writes `i18n/de.json` with every
   English text and an empty translation.
2. Translate the values. Set `meta.name` to the language's own name
   (for example `Deutsch`). Keep `{0}` and `%d` where they are.
3. `python tools/i18n_check.py` checks the file (placeholders, duplicates).
4. Rebuild. The language appears in Settings in the app and in the web client.
   For the Windows installer add a `[Languages]` line and the lines in
   `[CustomMessages]`.

Without rebuilding:

* **Host / web client:** put `<code>.json` in `<data>/i18n/`
  (for example `C:\ProgramData\Maarse\i18n\de.json`). A file there replaces a
  built-in one with the same code.
* **Android app:** `files/i18n/<code>.json` in the app's private folder.
* **Windows tray app:** `%ProgramData%\Maarse\i18n\<code>.json`.

## When you change a text in the code

The translation is found by the exact English text, so after you reword a
text the old translation no longer matches. Run

```
python tools/i18n_check.py --missing
```

to see texts in the code that a language does not have. The list is a help
and can show a few code fragments as well. New texts should be written in
English (see `CLAUDE.md`); add the translation to `i18n/da.json` in the same
change.

Texts that a screen builds from pieces (`"Sent " + n + " messages"`) cannot be
translated well. Write them as one text with the variable part in it
(`"Sent $n messages"` in Kotlin, `` `Sent ${n} messages` `` in JavaScript).

## Checks

* `python tools/i18n_check.py` (also in CI): valid JSON, `meta`, no extra
  placeholders in a translation, no duplicate keys.
* `cargo test -p maarse-host i18n` (language files are served and listed).
* `gradlew :app:testDebugUnitTest` in `android/` (the translation engine).

## Known limits

* The web client's `Language` button cycles through the languages. With many
  languages this should become a list.
* The language of a page that is opened from a file (`file://`) or copied
  elsewhere stays English unless `i18n.js` and `i18n/` are next to it.
* Long translations can break a narrow layout; look at the screen after
  adding a language.
* Not verified on a physical device: the Android language switch was
  compiled and unit-tested, the web client, the server pages, the host routes
  and the tray app build were tried in a browser or built on Windows. The
  Inno Setup script was edited but not compiled (Inno Setup is not installed
  here).
