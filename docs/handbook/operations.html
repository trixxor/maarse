Operations and diagnostics

Tools for running, checking and trusting a network.

TL;DR

What: Operations are the tools for running and checking a network: signed firmware updates, a status page, ping and trace route, a network crawl, a DHT check, a range test, position and telemetry, an MQTT bridge to Home Assistant, and a recovery phrase for your identity.

Why: A mesh is only trusted if you can see what it does. These tools let you check that your repeater is healthy, your route is good and your backbone is connected, without leaving your chair.

Strengths

  • Firmware updates are signed and run from the host over USB, Bluetooth, Wi-Fi or the network
  • Ping test, trace route and network crawl show loss, round trip, hops and SNR in both directions
  • A range test measures real distance with GPS and exports CSV
  • Home Assistant discovers battery, position and telemetry automatically
  • A 24-word recovery phrase restores your identity

Good to know

  • Updates over LoRa are shelved: too slow
  • The ping and crawl pages on Android are compiled but not run on a device
  • Firmware update from the host is not tried on hardware
  • No field results exist yet: the range test is the tool to make them

Mixed: see each section.

Firmware updates

Radios attached to a host are listed in the web client and the Android app with an Update button, from a GitHub release or your own build. A node accepts an image only if it is signed with its built-in release key, made for its own board, with a newer version. OTA is disabled with a missing, weak or development key. Updates over LoRa are shelved, because 323 KB takes about 1.6 hours per hop at SF7 and days at SF9 (decision 0002).

Position, telemetry and Home Assistant

Position is off by default. You can choose its precision (off, about 10 km, about 1 km, precise); the node sends it rounded to the middle of a grid cell, and only precise sends the exact position, after asking. Telemetry (battery, uptime, energy status) is opt-in.

A host can publish telemetry, positions and channel messages to an MQTT broker, and the first time a node sends telemetry, Home Assistant discovers it with battery voltage, battery percent, energy status, uptime, temperature and hops, grouped as one device per node.

Backup and recovery

Under Backup you can create an identity from a 24-word recovery phrase or restore one. The phrase is made and shown only in the browser and never stored; you must confirm three random words before it is installed. There is no back door: whoever has the phrase is you. If you lose it, nobody can restore the identity.

IP tunnel

Every node has an IPv6 address derived from its Må:rse address, and a host can tunnel IP over the mesh. It is optimised for LoRa with header compression and one-packet TCP segments. bench-tested A ping -6 over LoRa took about 1.45 s round trip (4.2 s the first time with route and key), measured between a Heltec V4 and an XIAO nRF52840 at SF9. Use mosh over LoRa rather than SSH; web and file transfer are not realistic.

Offline map

A host can keep a free offline map of Denmark (OpenStreetMap data, a 22 MB overview or a 185 MB detailed version) and serve it to clients. The host side is built, the clients not yet.

Technical details

  • Trace route (command 0x20): a probe packet follows the known route, and every repeater appends the SNR it heard. The packet ID is computed over the fixed part only, so implicit per-hop acknowledgements work as for other packets. A final byte via chooses LoRa only or internet only; firmware ignores it.
  • Noise floor: the radio library does not give the instantaneous RSSI, so it is estimated from received packets as N = RSSI − 10·log10(1 + 10SNR/10), as a moving average.
  • Position is carried in the announce's app data after the FS field, at most 67 of 99 bytes in total, so older nodes ignore it.
  • MQTT topics: maarse/status, maarse/node/<address>/telemetry, …/position and maarse/channel/<channel>, JSON, QoS 0.
  • IP tunnel: a random session key is sent once encrypted, after that traffic goes as datagram packets with 28 bytes of overhead and no end-to-end acknowledgement; the key changes every 5 minutes. The IPv6 header (40 bytes) is compressed to 2 to 7 bytes; TCP gets MSS 142.
