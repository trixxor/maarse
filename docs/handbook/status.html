What works today

Every feature with the kind of evidence behind it.

TL;DR

Nothing is field-tested. No range, loss or power measurement has been made outdoors. Behaviour is checked by automated tests, fuzzing, simulators, and bench tests on two boards on a desk. The cryptography has not been reviewed by outsiders.

Release v0.9.10 is the latest. The working copy has a few uncommitted changes on top (the ESP32 Wi-Fi hotspot gateway, airtime work on the branch airtime-compact-frame, and the documentation). Checked 2026-11-27.

Simulator results and their caveats

  • The simulator uses a log-distance path-loss model with exponent 3. Real radio is messier.
  • The comparisons with Meshtastic, MeshCore and Reticulum come from their documentation and from the simulator, not from measurements.
  • The simulator was optimistic about the old frame. With an honest overhead model, the car scenario went from 954 s and 97 % delivered to 2426 s and 81 %. Correcting the model made the numbers worse (decision 0011 in the decision log).
  • Load control and request quotas were measured and rejected, and the numbers are kept in the decision log.

How to run the checks yourself

  • cargo test --workspace runs the unit and integration tests.
  • tools/e2e_test.py starts hosts and sends real messages between them.
  • tools/dht_test.py starts three backbone hosts that only know one bootstrap, and checks that a message reaches a node the sender has never heard.
  • tools/stack_probe.py checks the ESP32 stack headroom after firmware changes.
  • The Mesh Lab and the Denmark simulator in the browser run the router in WebAssembly.

The longer list, with the field-test procedure, is in docs/verification/README.md and docs/FIELD-TEST.md in the repository.
