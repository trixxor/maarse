Features · Explanation

Pages

Small documents served over the mesh, like a notice board.

TL;DR

What: A page is a small document served by a host and fetched by address, like maarse://<address>/about. Pages are written in a light markup (.mu), compressed, and sent as an ordinary file, so a page works over LoRa. A page is never HTML, so it cannot run code on your device.

Why: A village, a club or a shop wants a notice board, a weather page or a menu that people can reach without internet. Pages give a mesh something to read, not only something to say.

Strengths

  • Works over LoRa: a page is a compressed file of up to 8 KB, or 1 MB over the internet
  • Safe by design: markup, not code
  • Notice boards, locked pages, columns, cards, colours and small widgets
  • Pages you opened are cached in the browser and can be read offline

Good to know

  • Firmware nodes fetch pages but do not serve them: a host serves
  • A page over the file limit is replaced by a short error page
  • At most 5 pages per 30 seconds from the same node

tested unit tests and page-limit regression tests. Not run on hardware. Five demo pages are live on the backbone node under /demo.

How a page travels

  1. You type an address. The client sends a page request to that node.
  2. The host answers with a file: the page compressed with raw deflate, named after the path.
  3. The client shows it as a page only because you asked for exactly that page from exactly that node. A file that merely claims to be a page is shown as an ordinary file.

What a page can look like

The whole look is written in the page's own .mu file: page settings (background, colours, font, grid, a ticker), columns and cards, effects, small widgets, notice boards and locked pages that only listed people may open. The full designer reference, with examples, is the Pages design guide on the project's site.

What a page can do

  • Show text, links, columns and cards
  • Host a notice board people can post to
  • Lock a page to chosen addresses
  • Be fetched over LoRa, with a per-chunk acknowledgement
  • Be edited in the server dashboard's Pages tab, with a file editor and stats

What it cannot do

  • Run scripts: there is no code in a page
  • Point outside the pages folder: paths may only contain a-z 0-9 - _ . /, at most 60 bytes, with no ..
  • Be served by a radio board

Protocol and limits

  • The client sends a request for a path. The node answers with an encrypted direct message of the page content type, and the host replies with a file whose MIME type is text/x-maarse-page;deflate.
  • Files live in <data>/pages/: index.mu is the root, about.mu is /about, weather/index.mu is /weather.
  • Same limits as files: 8 KB compressed over LoRa, 1 MB over TCP. A missing page returns a short "Not found" page.
  • The page server serves regular files up to 2 MiB only. Links, special files and reparse points are excluded, and image size is limited. The operator must protect the data directory against concurrent local changes.
  • The browser keeps the latest 30 pages for offline reading.
