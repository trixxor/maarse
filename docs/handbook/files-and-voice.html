Files, pictures and voice

What you can send, how big, and how long it takes.

TL;DR

What: Må:rse sends pictures and files encrypted, in small chunks with an acknowledgement for each: up to 8 KB over LoRa and 1 MB over the internet. Voice messages are recorded with the Codec2 codec at 1200 bit/s, about 1.5 KB for 10 seconds, and sent as an ordinary file. Live calls use Opus over the internet only.

Why: People want to send a photo or a voice note, but LoRa is slow. The app tells you before you send how big it can be and how long it will take, and shrinks pictures to fit.

Strengths

  • Encrypted chunks with a random key per file
  • The app says how big a file can be on the route, and how long it will take
  • Pictures are scaled down automatically
  • A file for an offline person waits in the host's file mailbox, sealed so the host cannot read it
  • Voice notes are small enough for LoRa

Good to know

  • Over LoRa a picture is small, and takes minutes: roughly 2 minutes of airtime for 8 KB
  • A radio board handles one file at a time in each direction and does not keep files in its flash
  • Calls need the internet all the way, and Chrome or Edge in the web client
  • Files over LoRa on firmware are not tested on hardware yet

bench-tested file transfer between hosts and boards; one measured case went from 157 s to 66.6 s with pull and batch transfer. Not field-tested.

The limit depends on the route

Before a file is sent, the client asks the host what the limit is for that contact, and shows the answer in plain words, for example "The picture is sent over LoRa and scaled down to 8 KB (about 2 min. airtime)" or "Sent over the internet (up to 1 MB)".

RouteLimitWhy
Internet all the way (the recipient and every hop are known hosts)up to 1 MBTCP is fast

If the host is in doubt, it never assumes TCP. A file over 8 KB is never sent along a route that is not internet all the way: the chunks are held back and the file goes into the file mailbox.

Voice

Tap the microphone in a direct conversation to record (at most 20 seconds) and tap again to send. The client downsamples to 8 kHz and encodes with Codec2 at 1200 bit/s: 10 seconds take about 1.5 KB, small enough to send over LoRa as a file. The recipient decodes and sees a player.

Calls: the Call button appears in a direct conversation through a host. Audio is Opus at 16 kbit/s in 20 ms frames, sent encrypted. A host only sends calls when the recipient is reached over the internet all the way; otherwise it answers that the call is not possible. Calls over LoRa are not possible.

Formats, mailbox and limits

file ID (u64) | chunk index (u16) | ChaCha20-Poly1305(file key, data) | tag (16)

CHUNK_OVERHEAD = 26 bytes, so each chunk carries 212 − 26 = 186 bytes of data. The file key is random per file and travels in the encrypted file offer. The host checks size, digest and chunk geometry, and allows at most 32 active incoming files, 8 per sender.

Files are never put in a radio board's flash, because one file would fill the 8 KB of mailbox flash completely. A received file is held in RAM until a client connects, and is overwritten by the next file. The content of files is not stored in history.

Voice format

"C2" | mode (5 = 1200 bit/s) | frame count (u16) | frames, 6 bytes per 40 ms. Codec2 comes from maarse-voice, a pure-Rust implementation compiled to WebAssembly for the web client and used over JNI in the Android app. Hosts and firmware do not know the format: they just send the file (MIME audio/x-codec2).
