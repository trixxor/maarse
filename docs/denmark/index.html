Attacks on alerts

Alerts v2 are checked with the real code (maarse-crypto alert): a forged alert has a bad signature and is dropped by every node; a replay is the same signed bytes sent again later: shown nowhere twice, and dropped everywhere once it has expired. Counts are in the Alerts list (Send).

Lost device, restored from the recovery phrase

The device is gone; after the time below a new one is restored from its 24 words (real maarse-crypto recovery): same address, but contacts, routes and history start empty. Its mail comes from the post offices. Phones have the same button (↺) in their window.

Flood a host over the internet

A host or app user sends junk to every internet link it has for 60 s. The receiving hosts run the real guard (maarse-hostrules): over 100 packets/s the extra is dropped; a link that keeps going is banned for 10 min. Results › Attacks and the guard. Switch the guard off in Build › Features to compare.

Internet

Servers that lose links find new ones through the seed DNS name (the seed hosts in Copenhagen and Aarhus), the hosts they knew, and the DHT. Hosts behind NAT cannot be connected to.

Random failures

Reboots

Off and on again: routes, neighbours and kept messages are lost; contacts too, unless "contacts survive a reboot" is on (Build, Features). Uses the node kind chosen under Areas.

Phones

Add up to 10 phones. Each runs the Android app (or the web client) on a node in this world: a new spot on the map or in a town, or an existing node, with internet and/or a LoRa radio. What you send travels through the simulated radio, hosts and internet. Press play: nothing moves while the clock is stopped. Drag a phone, dock it (⇥), minimise it (–) or close it (×); phones stay open in every mode, so you can break the network and watch them.
