Roles · Explanation

Server

The always-on host that lets other hosts find each other.

TL;DR

What: A server (maarse-server) is a host built for the internet: a VPS, a rack machine or a Raspberry Pi with an open port. Other hosts find each other through it, hosts behind NAT are relayed, it keeps copies of mail, and an admin dashboard shows what passes through.

Why: A backbone needs a few always-on, reachable machines to begin with. Without them, two hosts behind home routers cannot find each other.

Strengths

  • Hosts find each other through it: it is a DHT node
  • Relays hosts that cannot open a port, still end-to-end encrypted
  • Keeps mail copies for offline people
  • Admin dashboard with node census and map, destinations, routes, delivery times and live traffic
  • Debian/Ubuntu installer that sets it up as a service

Good to know

  • The open backbone is shared public infrastructure, not anyone's personal inbox
  • The dashboard is plain HTTP unless you put HTTPS in front
  • It sees destinations and routes of the traffic it relays, though not message contents

What a server does on the network

  • Hosts find each other through it. It is a DHT node. A host that points at it finds other hosts wherever they are.
  • Relay for hosts behind NAT. A host that cannot open a port connects out to the server, which publishes the addresses it reaches through it. Messages stay end-to-end encrypted.
  • Mail copies. As a public DHT node it is one of the replica hosts that keep mail for offline nodes.
  • Stays connected. It keeps at least 6 backbone links, spread over the DHT, and saves the nodes it has seen, so after a restart it finds the network again even if every seed is gone.
  • Says what it offers. Every host tells the backbone whether it keeps mail, how much room is left, whether it relays, its regions and its version. Replica post offices are only picked among hosts that keep mail.

The dashboard

At http://<server>:8080/ an admin password is needed. At first start a random password is written to admin-password.txt in the data folder, and the log shows only the file path. The dashboard has a Connections tab with every link, its uptime and traffic, Close and Block buttons, the block list and temporary bans. Other tabs show the node census with a map, destinations, routes, delivery times, modem counters and live traffic. A Pages tab and a Settings tab sit alongside, and a Share live traffic option feeds the real-network view of the Denmark simulator.

Shared infrastructure

The default backbone node (nj01) is public infrastructure that everyone shares. Do not treat it as your own mail server. If you want a private inbox, run your own server or your own host.

Run your own

sudo bash scripts/install-server.sh

On Debian or Ubuntu this installs the server as a service and asks for the settings. For public access put HTTPS in front with a reverse proxy such as Caddy and Let's Encrypt, and require the access key. An old phone on Wi-Fi and a charger can also be a server (Android app, Server on this phone), but mobile networks cannot be reached from outside, so it stops by itself when the phone leaves Wi-Fi or the charger.

Choices and technical detail

  • --no-post-office: keeps no mail for others. Mail from its own side still goes to the recipient's replica post offices.
  • --mail-quota-mb N: at most N MB of mail for others. When full, new mail is refused and the sender is told.
  • --no-relay: publishes only the addresses it reaches over its own radio.
  • --min-peers: keeps at least that many backbone links (server default 6).
  • A packet with a fixed route goes only to the link of its next hop (learned from traffic). A retry of the same packet within 10 seconds goes to every link, so a wrong guess never costs a message.
  • A Wi-Fi modem needs a key on a server: the host sends a random challenge and the modem answers with a hash of key and challenge, so the passphrase never crosses the network. No valid answer within 10 s closes the link.

Note: the options above are for server operators and appear here because a server has no person at a keyboard. For an ordinary host, everything is set in the web client.
