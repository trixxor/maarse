Må:rse pages

Small web pages that travel over LoRa radio and the internet backbone. Everything a page looks like is written in its own .mu text file, a page is usually 1–2 KB on air, and it never runs code or loads anything from outside.

Principles

The design lives in the .mu file. The browser in the PC host's web client and in the Android app only draws what the file says. There are no themes built into the browser: a newspaper, an old BBS or a dashboard are all just a few lines at the top of the page.
Nothing is fetched from outside. A page cannot load fonts, scripts, pictures or anything else from the internet. It works with no internet at all (over LoRa only), and reading it tells nobody but its node that you read it. Pictures come from the same node and only when you tap them.
Small enough for LoRa. Over LoRa a page may be at most 8 KB compressed; most pages are 1–2 KB (about 10–20 seconds of air). Markup is short and repeats, so it compresses well. Pictures cost nothing until someone taps them.
Safe. MU is not HTML. A page from a stranger can never run code; colours are checked before use, and links out of the network are shown as text, never opened.

Put pages in <data>/pages/ on any maarse-host or maarse-server: index.mu is the front page, news.mu is maarse://<address>/news, and demo/index.mu is maarse://<address>/demo. Links are written from the top folder: [News](demo/news).

The page

Lines starting with @ set up the whole page. They can stand anywhere and are never shown. (An @ line inside a code block is an example, never a setting.)

WriteDoes
@title Hals Havn BBSThe page's title (address bar, bookmarks), like <title>. Without it: the first heading.
@bg #fbfaf6Background: a colour, #0b1220..#0e1726 a gradient, … dots a halftone dot pattern, … glow #1f3a66 #3a1f5c two soft glows.
@fg #151515 · @link #0969daText and link colour. With its own background, named colours (red, blue …) pick the shade that reads on that background.
@font serifserif, sans or mono. See Fonts.
@width 75Reading width in characters. Without it the page uses the whole pane.
@grid 80x25A fixed text screen: every line is one row and keeps its spaces, the font is scaled so 80 columns fit. For BBS and terminal pages.
@ticker ⚠ GALE WARNING …A band at the top with text running across.
@dropcapThe paragraph after it starts with a big first letter.

Colours: red orange yellow green blue purple grey cyan magenta white black or any #rgb/#rrggbb. Braces may hold each other: {tilt -3:{huge:{!#ff3b6b:HARBOUR}}}. An unknown colour or brace shows as plain text, so a page never breaks.

Widgets

Small drawings made by the browser from a few numbers, so they cost almost nothing on air.

Notice boards

A line @board [n] [list|slips|table|ads] puts a board on the page: the n newest notes and a line where readers write their own. The node keeps the notes (the newest 50, in <page>.board beside the page). A note is at most 100 bytes and a reader may write one a minute. Notes are shown as plain text, never as markup.

Locked pages

A page only some people can open. The lock is written in the page, but the node keeps it: someone not on the list never receives the page. Nobody can pretend to be someone else, because a page request is a sealed message made with the sender's own key, and an address is the fingerprint of that key.

@allow 256665f180b8e3ce156fd52764c98012     one person, by their full address
@allow group crew                          a group: a line "crew <address> <address> …" in pages/.groups
@allow admins                              the node's administrators
@locked hidden                             others get "Not found" (they do not learn the page exists)
@locked until 2026-12-24                   open for everyone from that date

A lock in a folder's index.mu covers every page and picture in that folder. The lock lines are cut out before the page is sent, so the member list never leaves the node. A reader on the list sees 🔒 and how many may read it in the address bar; the browser keeps a locked page in memory only, never in its offline copy.

Fonts

Use only these names. A page can never load a font from the internet: it would break the page without internet and tell a third party who reads it.

Today: serif, sans and mono, drawn with the fonts already on the reader's machine (Georgia/Times, Segoe UI/Roboto, Consolas/Roboto Mono). They always work; the exact letters differ a little from machine to machine.

Planned: a small set of free fonts built into the web client and the app, so a page looks the same everywhere and costs nothing on air: serif, sans, mono, display (headlines), slab, hand, typewriter and pixel (a real DOS screen font for BBS pages).

A name the browser does not know (a newer one, or a typing error) falls back to the nearest of serif, sans and mono; an older browser that does not know @font at all shows its normal font. The page always stays readable.

On a phone

The page is the same; the app fits it to the screen: columns become one column, cards go two to a row (a two-wide card takes the whole row), side pictures go full width, and an @grid text screen is scaled to the width.

Byte cost

MarkupCosts
A page setting (@bg #0b1220)≈ 12–40 bytes, once
A colour {red:…} / {#e6007e:…}6 / 10 bytes
A box >!red 6 bytes
Columns or cards≈ 10 bytes, plus 4 per card
A widget {spark #f80:1 2 3 4}its numbers, ≈ 20–40 bytes
A table3 bytes per cell
A picture lineits name; the picture only when tapped

The demo designs are 0.8–1.9 KB compressed. Repeated markup compresses to almost nothing.
