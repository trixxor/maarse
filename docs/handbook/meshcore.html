Features · Explanation

MeshCore

Reading and writing on MeshCore from the Må:rse app.

TL;DR

What: A MeshCore gateway lets a Må:rse person read and write on the MeshCore network from the Må:rse app, through a radio gateway that is reached over the internet backbone. The two radio protocols differ, so a Må:rse board does not talk to a MeshCore board directly. The gateway is how they meet.

Why: MeshCore has a large community. A person who lives in both worlds should not need two apps and two identities.

Strengths

  • MeshCore chats, nodes and repeaters appear next to Må:rse in the same app, behind a switch
  • A MeshCore identity is created for the person, and linked devices share it
  • Log in to MeshCore repeaters, rooms and sensors, and see status and telemetry
  • Access is granted per person by the server's operator

Good to know

  • The gateway needs the internet to reach the backbone: it is not carried over a LoRa-only link
  • MeshCore message size limits apply: 90 bytes in channels, 60 in direct messages
  • Only some repeater commands were checked on a real repeater

working copy Checked on a physical repeater: login, ver, status, telemetry, get name, get radio, get tx, get flood.max, neighbors, region. Not checked: the set commands, reboot, setperm, region changes and changing the radio settings.

How it fits together

  1. An operator runs a radio gateway: a Heltec V4 with the MeshCore gateway firmware that reaches a backbone server over Wi-Fi.
  2. On the server's dashboard, under Connections → MeshCore gateway, the operator sees whether the gateway and the radio worker are connected, and grants or revokes access by Må:rse person address.
  3. On Android or in the web client, open Account → MeshCore, enter the backbone's HTTPS address (the open backbone is used when none is entered), and choose Check access. Once granted, choose Create MeshCore identity.
  4. A Må:rse | MeshCore switch appears in Chats and in Nodes.

What you can do

  • Chats: Public, joined channels and direct messages, newest first. A channel message shows Heard by N repeaters with the best SNR; a direct message shows Delivered once acknowledged. A #local-style hashtag uses MeshCore's hashtag key.
  • Nodes: scan for nodes in direct range, send a flood advert (repeaters pass it on) or a zero-hop advert (only direct range), filter by repeaters, chat, rooms and sensors, and star favourites. Favourites are stored per person on the backbone.
  • Repeaters, rooms and sensors: log in with the node's own password, which is not stored. The admin password opens Status, a Command Line and Settings. The guest password gives Status and Telemetry.
  • Name: your Må:rse name is also the MeshCore node's name, sent with the next advert.

Limits to know

  • When MeshCore is not reachable the switch is grey and says why: the node is not connected, the backbone cannot be reached, the account has no access, or the gateway is not connected.
  • Two people on the same gateway hear each other. A direct message needs the other's advert first.
  • Passwords pass through the HTTPS backbone and the worker queue. Keep that data directory private.

Details

  • The gateway worker supports seven named channels in addition to Public. A private channel takes its 16-byte key as 32 hex digits.
  • An administrator session expires after ten minutes. Change Identity Key is only possible over the repeater's USB serial port.
  • Both clients remember the name last seen for each MeshCore public key (500 keys) and show it in later lists. A node that never advertised stays unnamed; MeshCore has no name request.
  • The gateway address is stored per device, not synced between linked devices, but the account's identity is.
  • The earlier MeshCore USB bridge and its /mc socket were removed in the working copy.
  • Sending MeshCore chats as Må:rse messages over LoRa is parked (decision 0007).
