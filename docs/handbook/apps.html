Features · Explanation

Apps and clients

Android, the web client and the Windows app.

TL;DR

What: Må:rse has three ways to use it: the Android app (a native app with the host built in), the web client (served by a host, installable as an app), and the Windows app (a service with a tray icon). They show the same things in the same words, in English or Dansk.

Why: People use phones, laptops and desktops. The same features should be where you expect them on each, and one device should not be better than another.

Strengths

  • The same feature set and wording on Android and the web client, built together
  • The Android app has four connection modes: Bluetooth radio, phone as node, host elsewhere, server on this phone
  • The web client installs as an app and works offline once opened
  • Notification sounds you choose per kind of message
  • The Windows service installs signed updates

Good to know

  • The Android app is verified in an emulator: Bluetooth on a real phone has not been tested
  • Not in the Android app yet: the map, the range test and the alert issuing form
  • iPhone: Safari has neither Web Bluetooth nor Web Serial, so only a WebSocket to a host works

tested web client on Windows. Android emulator-verified. Windows installer working copy.

The Android app

A native Kotlin app. It runs the whole host inside the phone, in a foreground service in a process of its own, so a fatal error ends only that process.

ModeWhat it means
Radio over BluetoothThe app is a companion to a Må:rse radio.
Phone as nodeThe phone is a Må:rse node with its own identity, on the open backbone. The default role of the phone's node is client.
Host elsewhereFollow a host on another machine (your home PC, over VPN) with its access key.
Server on this phonemaarse-server for an old phone on Wi-Fi and a charger. It stops by itself when the phone leaves Wi-Fi or the charger, because mobile networks cannot be reached from outside.

Pictures, voice messages and calls work in the app. Remote administration of another Må:rse node is on the contact page under Manage this node. Not in the app yet: the map, the range test and the alert issuing form.

The web client

Served by a host at http://127.0.0.1:8080, and installable as a progressive web app: Install app in Chrome or Edge, or Add to home screen on Android. Over Bluetooth or USB it can use a radio directly, without a PC running a host. Once opened, it works offline.

  • Notifications when a message arrives in the background, and an unread count in the tab title.
  • Notification sounds for direct messages, channels and mentions: Default, Silent, six built-in tones, or your own file (up to 400 KB). Direct messages and mentions have a sound by default; channels are silent until you pick one.
  • One inbox on several screens: a host at home keeps the message history, so the phone, laptop and desktop follow the same conversations. A sent message shows on the others at once, and reading a conversation on one clears the unread counter on the others. File content is not stored.

The Windows app

A service plus a tray app, installed together. The service runs the host and installs signed updates from GitHub releases. The tray icon shows status and opens the web client. The service starts the tray app in the signed-in user's session when none is running. working copy SmartScreen shows a warning for the installer, which is accepted.

Languages

The Android app, the web client, the server pages, the web flasher, the Windows tray app and the installer can be shown in English or Dansk. It follows the device, and Settings → Language chooses by hand. A text without a translation is shown in English. A language is one file, i18n/<code>.json, and a new one can be added without rebuilding by putting the file in the data folder.

Technical details

  • The Android UI talks to the embedded host like the web client does: the companion protocol over WebSocket on 127.0.0.1:47080, with an access key, because every app on a phone can reach loopback.
  • The app is built with python tools/build_apk.py, which runs Gradle and builds the native library with cargo-ndk. It needs the Android SDK (platform 35, NDK 27), JDK 17 and Rust Android targets.
  • Hosting the web client yourself: put the files in maarse-client/ on any https static host and bump VERSION in sw.js.
  • A radio over Bluetooth needs Chrome or Edge on a computer or an Android phone. On iPhone only a WebSocket to a host works.
  • Android language switch is unit-tested but not tried on a device. The Windows installer script is not compiled.
